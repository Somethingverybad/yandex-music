# YaMusic Widget

Кроссплатформенный десктопный клиент Яндекс Музыки на Electron: **мини-плеер-виджет поверх окон** плюс полноценное окно сервиса с кнопками скачивания треков, альбомов и плейлистов.

Проект вырос из [ya-music-desktop](../ya-music-desktop) (Python + pywebview, только Windows). От него унаследованы инъекция кнопок «Скачать» в интерфейс ЯМ и логика загрузчика; всё остальное переписано на Node, движок — Chromium, поэтому приложение одинаково работает на Linux, Windows и macOS.

## Что умеет

- **Виджет-плеер** поверх всех окон: обложка, название, исполнитель, прогресс с перемоткой, prev/play/next, «мне нравится», скачать текущий трек. Перетаскивается мышью, помнит своё место, есть компактный режим.
- **Стеклянный вид**: WebGL-линза с преломлением, хроматической аберрацией, подсветкой кромки и бликом. На macOS и Windows дополнительно включается системное размытие фона за окном (vibrancy / acrylic).
- **Иконка в системном трее** со своим меню (управление треком, показать виджет, настройки) и **иконка в панели задач**: свёрнутый виджет возвращается кликом по ней.
- **Полное окно Яндекс Музыки** с кнопками «Скачать» рядом с треками, альбомами и на страницах плейлистов (скрипт `src/inject/inject.js` из исходного проекта).
- **Скачивание** в MP3 с ID3-тегами и встроенной обложкой: трек, альбом целиком, плейлист (в том числе редакционный по uuid-ссылке). Выбор битрейта, четыре схемы раскладки по каталогам, пропуск уже скачанного.
- **Живёт в трее**: большое окно можно закрыть, музыка продолжит играть — управление остаётся в виджете и в меню трея.
- **Интеграция с системой**: MPRIS на Linux (панель GNOME/KDE и аппаратные медиа-клавиши работают даже в Wayland), глобальные медиа-клавиши там, где они доступны.
- **Блокировщик рекламы** на уровне сети и DOM, автопринятие cookie-баннеров.
- Сессия Яндекса и токен сохраняются между запусками.

## Запуск из исходников

Нужен Node.js 20+ (проверено на 24).

```bash
cd ya-music-widget
npm install
npm start
```

Если `npm install` не выполнил postinstall (npm 11 блокирует скрипты по умолчанию) и Electron не скачался:

```bash
node node_modules/electron/install.js
```

## Сборка

```bash
npm run dist:linux    # AppImage + deb
npm run dist:win      # nsis-инсталлятор + портативный exe
npm run dist:mac      # dmg
```

Готовые файлы появятся в `dist/`.

На Ubuntu 24+ (и других системах без `libfuse2`) AppImage не запускается напрямую — либо ставьте `.deb`, либо запускайте образ так:

```bash
"./dist/YaMusic Widget-1.0.0.AppImage" --appimage-extract-and-run
```

## Токен для скачивания

Для воспроизведения токен не нужен — достаточно войти в аккаунт в окне Яндекс Музыки. Токен нужен только для скачивания:

1. В окне ЯМ нажмите «Скачать» у любого трека — откроется окно ввода токена со ссылкой.
2. Перейдите по ссылке и авторизуйтесь. Приложение **само поймает** `access_token` из адреса после редиректа и сохранит его.
3. Если перехват не сработал — скопируйте значение `access_token` из адресной строки и вставьте в поле вручную.

Токен шифруется и лежит в каталоге профиля (см. ниже). В логи он не пишется никогда.

## Где лежат данные

| Что | Linux | Windows | macOS |
| --- | --- | --- | --- |
| настройки, токен, сессия | `~/.config/YaMusic Widget/` | `%APPDATA%\YaMusic Widget\` | `~/Library/Application Support/YaMusic Widget/` |
| музыка по умолчанию | `~/Music/YaMusic Desktop/` | `%USERPROFILE%\Music\YaMusic Desktop\` | `~/Music/YaMusic Desktop/` |

`settings.json` можно править руками (приложение при этом должно быть закрыто):

| Ключ | Значение |
| --- | --- |
| `download_path` | куда сохранять музыку |
| `download_layout` | `flat`, `artist`, `album`, `artist_album` |
| `preferred_bitrate` | `320`, `192`, `128`, `64` — берётся лучший доступный не выше указанного |
| `skip_existing` | не перекачивать уже скачанные файлы |
| `block_ads` | блокировщик рекламы |
| `widget_enabled`, `widget_compact`, `widget_always_on_top`, `widget_opacity` | внешний вид виджета |
| `start_hidden` | стартовать без большого окна (только виджет и трей) |
| `close_to_tray` | закрытие большого окна прячет его, а не выходит из приложения |
| `widget_glass`, `glass_options` | стеклянный вид и параметры линзы |
| `glass_backdrop`, `glass_backdrop_image` | что преломляет стекло: `artwork`, `image` (+ путь к картинке), `snapshot` |
| `widget_in_taskbar` | показывать виджет в панели задач |
| `ozone_platform` | графический бэкенд на Linux: `x11`, `wayland`, `auto` |
| `password_store` | хранилище ключей на Linux: `gnome-libsecret`, `kwallet6`, `basic`, `auto` |

## Стекло

Виджет рисует стекло сам, шейдером в `src/renderer/glass-gl.js`: SDF скруглённого прямоугольника задаёт форму, суперэллиптический профиль — «выпуклость», дальше идёт преломление по Снеллиусу с настраиваемым IOR, хроматическая аберрация, кромка и блик. Оптика портирована из `shaders/glass.frag` расширения [Liquid Glass for GNOME Shell](https://github.com/ryohsuke1231/liquid-glass) (MIT, © Ryosuke Watanabe).

Важное ограничение: **страница не видит того, что находится за окном приложения**. Системное «настоящее» стекло есть только на macOS (`vibrancy`) и Windows 11 (`backgroundMaterial`) — они включаются автоматически. На Linux такого API нет: Mutter не даёт приложениям размывать содержимое под своим окном. Поэтому линза преломляет:

- **обложку текущего трека** (по умолчанию) — стекло перекрашивается вместе с треком;
- **свою картинку** — например, ваши обои: пункт меню «Фон стекла: своя картинка…». Из неё берётся ровно тот участок, который приходится на позицию виджета, так что на однотонном рабочем столе это неотличимо от настоящего стекла. Никаких системных запросов;
- **снимок экрана под виджетом** — пункт «Фон стекла: снимок экрана». Виджет на кадр прячется, чтобы не попасть в собственный снимок. В Wayland захват идёт только через xdg-desktop-portal, поэтому система каждый раз спрашивает разрешение — обойти это приложение не может, и само по себе снимков оно не делает.

Параметры стекла лежат в `settings.json` в `glass_options`: `ior`, `displacement`, `chroma`, `thickness`, `blurStrength`, `tint`, `rimIntensity`, `specular`.

## Трей и панель задач

Иконка в трее рисуется собственным StatusNotifierItem (`src/main/tray-sni.js`) поверх DBus, а не встроенным `Tray` из Electron: встроенный отдаёт оболочке только имя иконки и временный каталог темы, и расширение GNOME ubuntu-appindicators такой индикатор показывает пустым местом. Свой SNI передаёт иконку пикселями и меню через `com.canonical.dbusmenu`. Если StatusNotifierWatcher в системе нет, приложение откатывается на обычный `Tray`.

Виджет по умолчанию присутствует в панели задач: пункт меню «Свернуть в панель задач» убирает его, клик по иконке — возвращает.

## Как устроено

```
src/
  main/
    index.js        точка входа: окна, трей, IPC, перехват OAuth-токена
    config.js       настройки и шифрованное хранение токена
    ym-api.js       клиент API Яндекс Музыки и подпись ссылок на mp3
    downloader.js   скачивание, раскладка по каталогам, ID3-теги, обложки
    mpris.js        интеграция с медиа-панелью Linux
    tray-sni.js     иконка в трее через DBus (StatusNotifierItem + dbusmenu)
    wallpaper.js    поиск обоев рабочего стола
  preload/
    yandex.js       мост window.pywebview для inject.js + канал состояния плеера
    widget.js       узкий мост виджета
  inject/
    inject.js       кнопки «Скачать», модалки, адблок (из ya-music-desktop)
    player-bridge.js драйвер плеера: читает mediaSession и управляет сайтом
  renderer/
    widget.html/css/js   интерфейс мини-плеера
    glass-gl.js          стеклянная линза на WebGL
```

Ключевая идея: **звук играет полноценная страница `music.yandex.ru`** в скрытом окне, а виджет — только пульт. Состояние читается из `navigator.mediaSession` и активного `<audio>`, команды идут сначала в обработчики, которые сайт сам зарегистрировал в mediaSession (их же дёргает система), и только при их отсутствии — кликами по кнопкам плеер-бара. Поэтому переключение треков не ломается при очередном редизайне ЯМ.

## Известные ограничения

- Кнопки «Скачать» опираются на вёрстку ЯМ и могут пропасть после обновления сайта — селекторы лежат в `src/inject/inject.js`.
- Id текущего трека в режиме «Моей волны» из плеер-бара не читается; при скачивании такого трека он ищется по названию и исполнителю.
- Треки, недоступные в вашем регионе, пропускаются и попадают в список ошибок.
- На Linux по умолчанию используется X11-бэкенд (через XWayland): нативный Wayland-бэкенд Chromium падает на части систем. Переключается настройкой `ozone_platform`.
- При частых перезапусках Яндекс может показать капчу — она решается прямо в окне приложения.
